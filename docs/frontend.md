# Frontend conventions

Install Node.js 22.19 or newer and pnpm 10.24.0 (the version pinned in `package.json`), then run `pnpm install --frozen-lockfile`. Use `pnpm check` for validation and `pnpm build` for a production build.

The hub and writing workspace share Arc's semantic tokens and installed components. Import `components/arc/foundation.css` once in `src/renderer/src.tsx`. Keep page styles in the renderer's page stylesheet; use documented component props and layout classes rather than targeting CSS module internals.

Import shared motion values directly from `components/arc/motion-tokens.ts` (or `../motion-tokens` inside an Arc module). Breadcrumb links render native anchors; callback-only navigation renders buttons. There is no app-wide link or image adapter configuration.

The app currently stays in dark mode regardless of the OS appearance. `index.html` sets the startup theme; keep light theme tokens and selectors available for future support. The repository-import journey checks light-platform startup and platform theme changes while retaining dark colors.

Run development through `pnpm dev`, which starts the local Notion OAuth adapter and watches both the desktop backend and preload modules. It uses `.ai-docs/development-profile` by default, separate from the installed app; `GITORIAN_DEV_PROFILE` can choose another development profile. See [OAuth development setup](notion-oauth.md). Shared command-schema changes must rebuild and restart the backend alongside renderer updates; otherwise newly added UI commands can fail with an invalid discriminator from the older running schema. When changing the development launch command, restart an already-running dev session once to pick up the new watcher.

`pnpm smoke:dev-reload` exercises this through an isolated Electron IPC fixture: folder import initially fails against the old command schema, then becomes accepted after the shared schema changes and the development backend automatically restarts. `pnpm smoke` covers folder selection and actual repository discovery. `pnpm smoke:repository-import` verifies discovery without changes, checked-only imports, search preserving selection, cancellation, tracked/stopped repositories, empty selection, and single-repository review. It captures each step under `.ai-docs/screenshots/repository-import`, automating the native picker against temporary Git repositories and slowing real I/O to capture transient screens.

## Disclosure and feedback

App updates have a dedicated preload interface and main-process lifecycle, separate from journal snapshots and activity refresh. The shared `AppUpdateButton` appears in both main headers only when a downloaded update is ready to install: an icon-only ghost button with a primary foreground status dot. Its accessible name and tooltip announce Update ready. Checking and downloading stay in the background without a header control. Only the update UI subscribes to progress. Arc ToastStack prompts once per ready version without moving focus. The Arc Popover retains Update now after notification dismissal. Download completion never restarts the app, and installation on ordinary exit is disabled. Update now checkpoints the mounted weekly draft through its existing save path, refusing pending image imports and restoring editing after failure. Settings must be saved/closed first. Production enables updates only for packaged Windows apps; the documented NSIS development configuration is used by the isolated verification harness. See [update verification](../.agents/skills/verify-gitorian/features/app-updates.md).

First-time hub setup uses Arc `OnboardingChecklist` with the local controlled `completed` prop. In this mode check indicators are read-only and actions navigate without marking completion. `useOnboarding` derives completion from real connection and tracked repository state. Visibility is a profile-local localStorage preference scoped by restore ID: active, dismissed, complete, or existing. Populated profiles bypass onboarding; completed setup stays retired after later disconnects. Hide/Show only collapses the checklist body. The independent onDismiss extension adds a tooltipped 32px close button after Hide; dismissal moves setup into a header Arc Popover with an Arc ScrollArea and no dismiss control. Onboarding hides the real overview until dismissal/completion. OnboardingActivityPreview supplies a static decorative timeline and repository outline below setup, with a readable heading/explanation outside its bottom-fading mask. It contains no records or controls, is aria-hidden/inert inside the illustration, and shares setup?s existing exit instead of pulsing as a loading state. WeeklyHub overlays the outgoing setup and incoming overview in one grid cell: a 120ms exit precedes 240ms opacity/transform reveals of stats and activity, staggered by 35ms. Reduced motion keeps fades without movement/stagger; keyboard dismissal is immediate. Completion waits for Settings to close before revealing the overview, and established overviews do not replay their entrance. The stepLayout="horizontal" extension puts copy and action in separate columns at container widths of 560px or more and stacks them in narrow cards. Setup actions open Settings through `initialSection`; closing Settings restores an available header control when its original action has unmounted.

`OnboardingSetupLayout` anchors the preview at a stable layout origin and follows checklist height through a ResizeObserver-driven transform. Its single compositor layer prevents fractional disclosure heights from repainting text at whole-pixel positions. Reserve the measured preview height in the parent so responsive wrapping and scrolling retain their natural layout. Keep the existing disclosure timing; an additional position tween would lag behind the card. Verify with `pnpm verify onboarding-disclosure`, which checks native glyph captures as well as DOM motion.

Do not use native `<details>` or `<summary>` elements anywhere in renderer UI. Their browser-default marker and presentation do not follow Arc. Use the installed Arc `Accordion` for expandable sections, `Popover` for optional content opened by an icon, and `Tooltip` only for short, nonessential hints. Do not imitate these components with custom disclosure markup.

Keep raw HTTP, Git, and exception diagnostics out of user-facing error states. Show what failed, a useful explanation, and the relevant recovery action. Import results may list affected folder paths and understandable reasons; internal error payloads do not need a disclosure or tooltip.

A diff load failure belongs inside the Diff tab as a centered, borderless Arc `EmptyState`: a plain error icon, title, optional explanation, and recovery actions. Do not add an Alert card above the tabs or wrap the state in another bordered panel. Loading, failure, unavailable evidence, confirmed empty changes, and loaded changes are mutually exclusive. Show an empty-diff message only after a successful response confirms empty changes. Preserve cached changes on refresh failure with a compact notice inside the tab. Details and Related stay usable.

The local Arc `EmptyState.iconVariant="plain"` extension removes the icon frame for pane states; the default remains `"framed"`. Keep layout styles on the pane wrapper rather than overriding component internals.

Background source warnings use a short one-line toast title and a `Review` action. The notification viewport may be wider on desktop but must stay within the viewport on phones. The local toast-stack responsive breakpoint moves actions below the copy at 24rem or narrower, keeping source-warning titles on one line on phones. Never truncate the title or force overflowing text to stay on one line.

## Corner radii

The radius definitions live in `src/renderer/components/arc/foundation.css`. Use these tokens for new UI and keep their values shared across pages.

| Token              | Value  | Use                                                     |
| ------------------ | ------ | ------------------------------------------------------- |
| `--radius-key`     | 4px    | Keyboard hints and tiny code affordances                |
| `--radius-inset`   | 12px   | Small nested list items                                 |
| `--radius-control` | 18px   | Activity rows, buttons, inputs, selects, and tab groups |
| `--radius-panel`   | 26px   | Popovers, menus, and bordered panels                    |
| `--radius-surface` | 34px   | Large contained hub surfaces and dialogs                |
| `--radius-pill`    | 9999px | Small activity filter chips and their project select    |

Do not redefine these tokens for an entire page. A filter chip may locally set `--radius-control: var(--radius-pill)`. Nested controls should follow Arc's concentric inset radii. Full-width pane boundaries stay square and share dividers; they are not floating cards.

## Activity lists

`ActivityFilterStrip` composes Arc `ScrollArea` and ghost arrow buttons in both activity toolbars. All chips stay on one row. Each directional arrow exists only while more content is hidden in that direction. Arrows sit in non-scrolling edge overlays with surface-colored scrims; appearing and disappearing never changes the chip viewport's width or origin. Arc's hover-only scrollbar stays hidden during unhovered scrolling, and the 24px edge fade reaches beyond ghost-chip padding. Focus reveals chips clear of the overlays and moves into the scroll region before a focused arrow is removed. ScrollArea's local `startOverlay`/`endOverlay` slots preserve keyboard order outside the scrolling viewport; its default `auto` scrollbar behavior is unchanged. Wider rows have neither overflow controls nor a second line. Keep vertical wheel events native (`wheelToHorizontal={false}`). Focusing a clipped chip reveals it horizontally without moving the activity list. Day and Projects use MorphSelect's local `portal` option: the surface keeps its existing morph, escapes the scroll mask, fits the viewport, and returns focus to the in-row trigger. Escape, search, selection and Tab retain the toolbar's logical order. Keep the panel mounted through its closing morph before restoring the inline surface. Verify with `pnpm verify activity-filters` and `pnpm verify activity-days`.

The hub and workspace share `ActivityDays`: All days previews five filtered records per day; a dated day filter shows that day's full list. Day appears before Projects in the activity toolbar, with the same compact gap as the other controls. Day headings show only the weekday and date. Expanded days survive filter changes within a visit and reset with the week. `ActivityDayRows` composes the local Arc Accordion's controlled, plain, trailing-trigger extension: an ellipsis timeline node exposes Show N more or Show fewer. Closed content is inert; the plain Accordion measures its content height and drives the returning scroll position from that same height. Browser scroll anchoring is suspended during collapse, and the destination is bounded by the final scroll range. The disclosure uses Arc's smooth spring, with instant keyboard and reduced-motion disclosure. The label crossfades without changing its width. Keep timeline connectors continuous across preview, extra rows and the trailing control. See `pnpm verify activity-days` for both real Electron entry points.

The hub, workspace, and related activity use `ActivityRow`: connected timeline nodes, a title, repository and branch metadata, an Arc status badge, and a short SHA or pull request number. Connect nodes only within each visible group. Rows have a borderless rounded hover background; selected rows add an inset hairline, filled timeline nodes and chevrons, and stronger status chips. Preserve native button behavior, workspace selection, and citation dragging. The installed Arc `Badge` has a local `animateChanges={false}` option for static records, keeping long lists free of per-row motion and resize observers; changing status controls retain the default animation.

Pull references display only the trailing number from real `repository-id:pr:number` IDs or sample `sample/pr/number` IDs. Bound the trailing column so the title and metadata retain priority. Each row draws its own incoming connector; hover and selection use the stronger border token so row backgrounds cannot hide the timeline.

`ActivityHover` moves one shared background between rows using Arc's morph spring, including across day groups. Pointer movement updates motion values without rerendering the activity records. Leaving the list or scrolling clears the highlight; resizing and filtering update its bounds. Keep the highlight noninteractive, preserve selected-row backgrounds, and snap motion when reduced motion is requested.

Timeline hover contrast travels with the background. A noninteractive SVG mirrors the connector and node borders in two paths (neutral and merged), clipped by the background's shared motion values. Only the portion covered by the moving background brightens, with no delayed per-row hover state. Measure paths on layout changes, not animation frames; preserve gaps between day groups and merged status colors.

Closed ghost `MorphSelect` controls use the same hover surface and foreground as Arc ghost buttons, with no pointer-hover border. Expanded menus retain their border.

The shared diff viewer uses `ChangedFilePicker`: an Arc `MorphSelect` search surface containing Arc `TreeView`, with compact single-folder chains, filename wrapping, full-path titles and a visible selected path. Search matches the whole path and expands matching folders. Selecting a folder only expands it; selecting a file changes the diff and folds the picker. Deleted files use their original paths, and renamed files use their new paths.

Local Arc extensions: `MorphSelect.renderTree` receives `{ id, query, selected, select, close }` and changes its popup semantics to a tree; search navigation transfers focus into the tree, Escape restores trigger focus, and Tab can move between the search and tree. `title` and `maxTriggerWidth` support bounded toolbar labels. `TreeView` adds lazy `hasChildren`, per-row `status`, and a decorative `loadingPlaceholder` after a branch's visible descendants, `id`, controlled `selectedId`, `TreeNode.title`, a `plain` variant, `wrapLabels`, `animateExpansion`, and `onEscape`. The embedded picker disables row size animations so the morph surface alone animates expansion, and uses semantic colors. Keep the tree's native keyboard navigation and the Arc scroll area. Bound the open surface to the diff pane's available width and height in the workspace and pop-out. Global app shortcuts treat focused trees like other composite controls.

## Writing workspace

The workspace has one layout: activity, writing, and inspector. It fills the viewport below its main header. The header uses Arc `Breadcrumb`; its Journal crumb returns to the hub. Equal outer grid columns center the date picker independently of the side controls. Desktop header padding is 8px vertically; at narrower widths the date moves into its own centered row. Below 1100px the inspector moves beneath the writing pane, and phones stack the panes with useful minimum heights. Preserve a readable writing measure inside the full-width pane.

Publishing is rendered into the last main-header slot by `WorkspaceDraft`, so autosave, publishing, and their pending state share one owner. Opening the workspace resumes its latest unfinished draft for that week, or offers to start a new entry if there is none. Published entries are not opened for editing. Creating another entry never overwrites a published entry.

Notion connection guidance belongs in the writing footer, keeping the editor clear. Offer the settings action when the connection or publishing destination is missing, while leaving local writing available. Citations update the entry without a main-header success banner.

Notion authorization continues inside one connection morph. The rounded leading field and circular revert button share the Confirm button?s 4px inset from the morph. Arc `Combobox.onQueryChange` supports remote results in the same popup; clicking an already-open input preserves its query. Arc `Combobox.renderTree` composes the portaled popup with `TreeView`; parent IDs are internal, while every visible label and tooltip contains only page names. TreeView's opt-in `selectBranches` separates chevron expansion from name selection without changing the file picker's default folder behavior. A node with `selectable: false` is a navigable group: its label or Enter toggles expansion, and it never receives selection state. Notion resolves block ancestors to enclosing pages and uses data-source names as non-selectable groups; database containers locate those groups without redundant rows. Ancestor reads are cached per discovery; inaccessible ancestors leave accessible pages visible, while transient errors retain Retry. The popup retains search ancestor context; no manual Refresh control is shown. The existing page picker stays available while indexed pages load. Its one search field filters known pages immediately and debounces Notion title searches by 250ms; a pasted Notion page link resolves that page directly. Search results keep ancestor context in the same tree. Expanding a page reads only its child pages (including children inside nested content blocks); expanding a data-source group queries only that source. Completed branches are reused during that selection session. Initial reads and title searches show three shimmering Arc Skeleton rows at the end of the popup, without visible progress copy or a spinner. Known matching pages stay available above them. Expanding a branch shows a small spinner on its row and one decorative skeleton after its current children until the read completes. The placeholder is excluded from keyboard navigation and the accessibility tree; the busy row retains a named polite status. Arc Skeleton adds opt-in `animation="shimmer"` and the `--skeleton-block-height` layout token, leaving existing pulse placeholders unchanged. Reduced motion stops both shimmer and rotation. The Notion section is an inline-size query container; confirmation rows constrain the field to the panel width and move controls beneath the heading when the panel is narrow, including at 200% zoom. Retry replaces loading feedback in place, and rate-limit waits retain the named row status. Feedback never appears under the selector. Query changes cancel obsolete reads; confirmation, cancellation, disconnect and restore cancel the whole selection session. Only completed reads enter the metadata cache. A new-page action replaces the picker with the inline Arc Input. Connected Notion shows its saved page icon/name and chevron inside a rounded selector face with the same height and rounded border as Disconnect and a transparent resting surface. Clicking the saved page keeps the same ConfirmMorph mounted through loading, page selection, error, saving and return. ConnectionSignIn connectedAction supplies this reversible connected action; its default remains disconnect. Notion owns a separate ConfirmMorph/useDisconnectTransition for disconnect and hides competing actions during either workflow. Disconnect owns a collapsible space that uses the shared 240ms zero-bounce spring, so the page morph moves continuously when that space is released or restored. Reduced motion changes the allocation immediately and keeps only the opacity transition. Cancel restores the saved destination and trigger focus. It does not load the OAuth app profile. Cancel preserves a confirmed destination; explicit confirmation saves immediately and is excluded from unsaved preference comparisons. Keep this flow free of secondary descriptions. Loading/saving use ConnectionSignIn's `expandPending` so narrow layouts keep the same row constraints from browser approval through selection. ConfirmMorph's `pendingContent` accepts the visual status while `pendingLabel` remains plain text. The pill keeps a measured numeric width after its first layout and retargets a 240ms visual-duration, zero-bounce spring from the current value instead of handing back to auto. Arc AnimatedCounter's local `variant="inline"` inherits text styling, reserves the final formatted width independently of its wheel animation, and uses transform/opacity for digit entry. Its display variant retains the registry defaults. Keep the rolling glyphs decorative and announce the complete progress phrase through the existing polite status. Notion discovery still reports its fetching/grouping lifecycle through the preload, while picker loading uses skeleton rows. The preload progress subscription uses a request ID and ignores canceled attempts. A bounded, validated metadata cache outside journal state/backups is scoped to the authorization token hash; fresh snapshots are reused for five minutes, stale snapshots refresh for the next picker open without moving current rows. Token rotation/replacement misses the cache; disconnect and restore clear it. Failed or canceled discoveries never replace a complete snapshot.

At 600px and below, Settings navigation moves above the content and uses horizontal Arc tabs, with matching keyboard orientation. This gives the connection morph enough width for its picker and both confirmation actions. The picker menu can be wider than its compact field, bounded to the viewport; long option labels expose their full text through a native title.

Keep word count, save status, and the Notion action in one footer row, with the status centered between equal outer columns when space allows. Only writing panes 460px or narrower stack the count and status beside the settings action. Use a pane container query, since the writing pane can be narrow within a wide window.

Keep sample state separate from real commands. The workspace header has no sample-data switch. Retain `workspace-sample.ts` and the explicit `?workspace=true&data=sample&week=2026-10-05` preview URL for design iteration and smoke tests; normal workspace navigation uses real data. Sample publishing is simulated. Detached reference windows remain read-only and send citations to the editable main workspace through the existing channel. They have no note form; citation results appear in the inspector footer.

Use Arc `ScrollArea` for constrained activity, writing, diff, details, related-item, and popup lists. Name each viewport for keyboard users. The hub uses a named full-height Arc ScrollArea. Native text controls and document scrolling outside constrained views retain native scrolling.

Search uses Arc `ExpandingSearch` to navigate weekly activity, including across the active list filters. Selecting a result opens its Details tab. Its local `expandedWidth="container"` option fills the header's available width and follows pane resizing.

The hub and workspace share `ProjectFilter` and `ActivityChart`. The project chip follows the day filter and uses Arc `MorphSelect` with search always enabled, an “All Projects” option, and the selected project name. The installed component has local `variant="ghost"` and `size="sm"` options for toolbar chips, and an Arc `ScrollArea` inside the expanding list. Toolbar pickers portal their expanding surfaces so the horizontal scroll mask cannot clip them. Other embedded MorphSelect uses retain their existing inline behavior. Daily counts are computed once for each activity list rather than formatting every activity date on each pointer movement.

In the workspace, keep the project picker and branch-history control in one nonwrapping group within the wrapping filter toolbar. They move to the next row together. Bound active branch text while retaining its complete title and accessible clear-action name; let that label shrink while preserving the picker and clear icon. Use the Arc button's stacked content slot for the history control so its content can shrink within the group. The group must not clip the expanding project menu. Verify idle, active and cleared layouts with `pnpm verify activity-filters`.

Hub activity details own their selection and request state in `HubActivityDialog`. Load details into that dialog directly so opening it does not rebuild the whole hub activity list. Keep its height stable, header and footer fixed, and content in a named Arc `ScrollArea`. Arc `DialogContent` supports `backdrop="dim"` for large data views to avoid repainting a full-page backdrop blur; other dialogs keep the default blur.

The daily activity preview uses Arc `BarChart` with three local, typed extensions: `compact`, `onActiveChange`, and `onDatumSelect`. Its small Arc popover follows the pointer, or the selected bar when using the keyboard. Show counts for commits, PR activity (including opened and merged events), and reviews; do not list individual activities here. The read-only summary must not intercept pointer events or extend its visibility when hovered outside the chart. Enter, Space, and tap also reveal counts. Keep the reduced-motion behavior and stable date keys.

Arc `Select` supports a local `variant="ghost"` for filter chips and `contentMinWidth` for wider menus, constrained to the viewport. Options can include a numeric `count`, displayed separately from the label with `--space-2` (8px). Filter chips share medium weight and `--leading-body`, so selects align with buttons. Omit the visible label for an icon or inline chip only when it has an accessible name.

The project chip follows PRs & reviews, shows the available project count at rest, and shows the selected project name when filtered. The Filters chip is icon-only and opens deliberate branch/history loading. Feature collection, definition, grouping, and filtering are outside the app scope. The shared model, backend commands, details controls, and sample data no longer contain feature groups.

Arc `TabsList` supports a local `edgeToEdge` option: the strip spans its pane with square outer corners while individual tabs retain their shared control radius. Related items reuse the activity row styles. Both writing and inspector footers use `--workspace-footer-height` (64px).

Activity details in the hub and workspace share `ChangeStatistics` and `ChangeCounts`. Totals open an Arc Popover with a category table; signs and accessible labels preserve the meaning of the addition/deletion colors. The shared `change-statistics` module owns path classification, complete totals, and parsed-patch line counting. File metadata retains counts independently of patch display limits; older metadata without counts reloads through the existing details command. Binary counts are excluded when identified, and unknown counts stay unavailable rather than becoming zero. Keep the selected file's path and counts visible in the Diff tab in both docked and detached inspectors.

The inspector has one activity title: a semantic heading in its persistent header, with reference and PR/review status beneath it. Details starts with metadata and preserves the original commit message or PR body. Shared section headings use primary foreground at weight 500. Repository values retain weight 500; branch and author values use primary foreground at weight 400. Dates, comparisons, and commit identifiers remain secondary, with technical identifiers in monospace. Missing values and metadata labels stay subdued.

## Settings

Keep settings layout in `src/renderer/settings.css`. Preserve the compact 850px by 720px desktop dialog, its control radius, header padding, muted save footer, and vertical Arc tabs. Both navigation and content use Arc `ScrollArea`; the content viewport fills the available height. Avoid adding settings overrides to the legacy desktop stylesheet. Fields use a two-column grid that becomes one column on phones; connection actions share a wrapping row. Keep descriptions to the information needed to make a decision.

Repository setup chooses a parent folder through the native picker and discovers Git working trees recursively. Skip links, dependency folders, and repository internals. Existing repositories are deduplicated by canonical path; resuming tracking preserves their identity and history. Comparison bases come from local and remote refs. Tracking uses an Arc switch and applies with the other repository settings on Save. The locate-folder button has a secondary background. Branch-specific overrides are not exposed in settings; retain existing backend values when saving a repository.

New repositories automatically select a recognized GitHub fetch remote: prefer `upstream` for fork contributions, then `origin`, then another GitHub fetch remote. HTTPS, SCP-style SSH and `ssh://git@github.com/` URLs are supported. Repositories without a matching remote remain local-only. Local Git acquisition continues alongside GitHub PR/review acquisition. `useWeekHistory` already requests missing coverage when repositories or GitHub identity change, including when periodic refresh is disabled; keep that single acquisition entry point. Explicit remote changes and Local only remain available in repository settings. Verify both setup orders with `pnpm verify github-import`.

Repositories use independently expandable Arc `ExpandableCard` components, keyed by repository id. Show the repository name and its full folder path in the card summary, with long names and path segments wrapping inside the card. Keep every card initially closed and preserve native disclosure keyboard behavior. Arc `SearchField` filters repository names and paths without changing the settings being edited. Its local `hideLabel` option keeps the search name accessible without displaying a heading above the input.

Pass repository fields as an `ExpandableCard` render function to defer mounting until the first expansion. Details stay mounted after that so closing preserves input state and reversing an animation remains smooth. Settings uses the dim dialog backdrop to avoid repainting the hub through a blur. The expanded repository layout starts with tracking and locate-folder controls, followed by history/comparison fields, fetch activity, remote, and author emails. Author emails use Arc `TagInput` for adding and removing addresses.

Folder import reports selection, discovery, and completed/total processing through the preload's `onRepositoryImportProgress` subscription. Unsubscribe when settings unmounts. `addRepositories` selects and scans a folder without changing tracked repositories. Settings temporarily replaces its content with `RepositoryImportReview`, preserving unsaved edits. Discovery shows a rotating spinner above its description, morphs to a check or X, holds the outcome briefly, then fades into selection or actionable error guidance. Reduced motion disables rotation and movement. Eligible repositories start checked; active tracked repositories are disabled, and stopped repositories can resume tracking. Search preserves selection; Select all and Deselect all apply to the whole scan. Cancel or Escape returns to Settings without importing. `importRepositories` submits the scan ID and checked paths, validated against the latest in-memory scan, then starts background processing. Show unreadable folders before confirmation. Animate and announce the button's real processing progress through the Arc button. Do not duplicate progress in the settings footer. Use `aria-busy` rather than the button's `loading` prop here: its loading presentation hides the text behind a spinner. Cancelled folder selection restores the idle action without an error.

`ImportProgressLabel` keeps progress copy stable and animates each changing number with tabular numerals. The import button uses the Arc stacked content slot so long labels wrap in narrow settings columns. Announce the current numbers once; hide outgoing animated numbers from assistive technology.

Connected GitHub settings show the avatar and username followed by Arc `ConfirmMorph` with `confirmMode="hold"` and `tone="danger"`. Return the real disconnect promise so failure and retry stay in the control. On narrow layouts the question stays available to assistive technology while the visible confirm/cancel controls fit in the settings column.

GitHub uses the thumbnail profile cache. Notion instead persists destination names and emoji or cached WebP icons with settings, and fills missing metadata through a nonblocking page lookup. ## Windows cursor visibility

Electron 44.5.1 bundles Chromium 152.0.7977.130, whose `HideCursorWhileTyping` path calls Win32 `ShowCursor` on the UI thread. Native file dialogs inherit the hidden cursor; their pointer events do not run Chromium's restoring filter. A wheel event in the app shows it again. Startup disables this feature on Windows while preserving other disabled features. Remove this workaround when the bundled Chromium includes [upstream fix a2be9ee](https://github.com/chromium/chromium/commit/a2be9eeac1d506dae63b2994cd605d83bb7622ea).

Header icon sizing belongs to `.hub-utility-icons`; the text-bearing Continue setup button keeps its intrinsic width, padding and independent hover target.
